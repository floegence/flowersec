# Flowersec 7 protocol security acceptance

Flowersec 7 endpoints use `flowersec/5`. This gate covers security properties of the standard direct and tunnel profiles, the invitation descriptor exchange, and the boundaries of the explicit HTTP Direct and private-loopback profiles. The [wire contract](TRANSPORT_V5_WIRE.md) and [threat model](THREAT_MODEL.md) define the authenticated projections and trust assumptions.

## Run the gate

Run `make security-v5-acceptance` from the repository root with the engineering Go, Rust, Node, TypeScript and Swift toolchains. Install `java`, `tamarin-prover`, `maude` and `z3` on `PATH`, and set `TLA2TOOLS_JAR` to the pinned release jar. `toolchains.json` specifies its SHA-256 and the Tamarin, Maude and Z3 versions. The runner uses `TMPDIR` for disposable prover state. See the [TLA+ releases](https://github.com/tlaplus/tlaplus/releases) and [Tamarin installation guide](https://tamarin-prover.com/manual/master/book/002_installation.html).

`make security-v5-model-check` runs the formal part independently and is included in `make nightly-check`. Each TLC baseline must finish exhaustive exploration of its finite state space. Each named positive witness must be reachable and each model fault must violate its designated invariant. Tamarin must verify every listed lemma with the expected quantifier, including reachability witnesses. A missing result, prover warning, timeout, tool mismatch or failing implementation test fails the gate. A witness demonstrates one possible successful execution. It makes no availability or eventual-progress claim.

## Trust and interpretation

- Tamarin quantifies over arbitrary concurrent modeled sessions. Issuance gives each endpoint pair a fresh PSK and one role instance per credential. Metadata can recur across issuances. The model uses ephemeral Diffie–Hellman with ideal hash, KDF, confirmation and authenticated encryption. Its record header and key inputs represent the wire domains symbolically. TLS validation, canonical decoding, trusted listener identity and the atomic authority operation are trusted boundaries in the handshake model. The credential and policy models examine selected transitions inside these boundaries separately.
- Honest routing ties tunnel completion to both authority records. The active-relay handshake proof assumes uncompromised endpoints, issuer and PSK. The separate disclosure proof starts with two matching honest shares. This boundary matters for compromise before completion. Full endpoint compromise gives access to application plaintext and live key material. Session rekey derives the next directional secret from existing secret state and public inputs, so exposure of that state persists along that chain.
- TLC covers the finite bounds in the table. The simultaneous-rekey model covers one overlapping transition per direction and a fixed stream set. The lifecycle model checks one bound session, two workers and one stream. The proof of the bitmap update uses the full production integer widths. The relation between the model actions and each SDK's source is supported by vectors and executable tests. A machine-checked refinement from all four complete source implementations remains open.
- TLS providers, cryptographic primitives, random generation, trusted time and SQLite filesystem semantics are assumptions. Deployment-level checks are required for snapshot rollback, power loss and key erasure. Side channels, resource exhaustion and progress under an indefinitely blocking peer have separate assurance requirements. The [test matrix](TEST_MATRIX.md) describes carrier and runtime coverage.
